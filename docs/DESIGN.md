# any2enforce — 设计文档

> 把常用编程语言自动转换为 EnforceScript（Arma Reforger / Enfusion 引擎脚本语言）的转换工具。
> 当前首选目标源语言：**Python**；架构上预留 Java / C# / TypeScript 前端。

版本：v0.1（设计基线） · 状态：设计 + 原型骨架

---

## 1. 目标与动机

EnforceScript 是 Bohemia Interactive 在 Arma Reforger（Enfusion 引擎）中使用的 C 风格、
静态类型的面向对象脚本语言（源码文件 `.c`，位于 addon 的 `scripts/` 目录）。它和 Python
在语法、类型系统、对象模型上差异巨大，手写迁移成本高、易错。本工具的目标是：

1. **自动转换**：把（受约束子集的）Python 代码翻译成语义等价的 EnforceScript 源码；
2. **可校验**：转换结果接入 Workbench 的 `ValidateScripts` 编译验证，形成闭环，而不是"生成完就不管"；
3. **可扩展**：前端（源语言解析）与后端（EnforceScript 代码生成）解耦，后续接入其他语言；
4. **诚实降级**：对无法 1:1 映射的 Python 特性，给出分级的诊断信息（error/warning/info），
   绝不静默生成语义错误的代码。

### 为什么先做 Python

- Python 标准库自带 `ast` 模块，前端零依赖、语法树稳定；
- Python 的缩进结构天然适合程序化遍历；
- 潜在用户群（工具链/仿真/原型代码）中 Python 存量脚本最多；
- Python 的显式类型注解（PEP 484）为类型映射提供了主要线索。

## 2. 目标语言速览（EnforceScript 关键事实）

> 本表已用真实 Reforger 脚本语料（`_reforger_code_full_v2/scripts`，6568 个 `.c`）校准，
> 逐条证据见 `docs/VERIFY.md`。❌ 项为语料确认不存在的语法，工具已降级。

| 主题 | EnforceScript（实测） |
|---|---|
| 文件 | addon `scripts/**/*.c`，无 import 系统，全部源码一起编译 |
| 标量 | `int` `float` `bool` `string` `vector` `typename` `entity` |
| 引用 | `ref` 托管引用：`ref Foo f = new Foo();`；**类类型声明/泛型参数必须 `ref`** |
| 容器 | `array<T>` `map<K,V>` `set<T>`；`.Count()`/`.Insert()`/`.Remove()`；**`map[k]` 下标读写合法** |
| 数组字面量 | `array<T> x = { ... };`（初始化式，**不是** `new array<T> { ... }`） |
| 类型推断 | 局部变量 `auto`（实测 `auto points = new array<vector>();`）；参数必须显式类型 |
| 类 | `class Foo : Base { ... }` 单继承；`override`/`sealed`/`static`；`private/protected/public`（默认可见性可省略） |
| 构造 | 与类同名、返回 `void` 的成员函数；**参数默认值合法**（`void F(int a = 3)`）；基类默认构造疑似隐式调用（⚠） |
| 控制流 | `if/else if/else`、`while`、`for (int i = 0; ...)`、`foreach (T x : arr)`、`switch/case/default`；**无三元运算符（❌）** |
| 字符串 | `string.Format("...%1...%2", ...)`（9 个 `void` 参数）；`+` 拼接合法；`Length/Contains/Substring/ToInt/ToFloat/ToString` 等 |
| 输出 | `Print(void var)` 接受任意类型；`PrintFormat(fmt, param1..param9)`；❌ 无全局 `PrintError/PrintWarning` |
| Math | `Math.Floor/Ceil/Pow/Mod/Min/Max/MinInt/MaxInt/AbsFloat/AbsInt/Clamp/Round/Sqrt`（全部 float 签名；❌ 无 `Math.Abs`） |
| 注释 | `//` 与 `/* */` |
| 空值 | `null`；`true`/`false`；强转 `(int)x` / `(float)x` 合法 |
| 字段访问 | **裸 `m_x`**（`m_` 前缀消歧，`this.m_x` 罕见）；静态字段 `s_` 前缀 |
| 命名参数 | `method(paramName: value)`（如 `ToFloat(default: 17.6, offset: 3)`） |

⚠ 剩余待实测项（已列入 `docs/VERIFY.md`）：int/int 除法结果类型、显式基类构造调用、
`@property` getter/setter 惯用法、运算符重载、回调/函数指针、`\uXXXX` 转义、科学计数法浮点字面量。

## 3. 总体架构

```
┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│  Source      │   │  Frontend    │   │  IR + Sema   │   │  Backend     │   │  Validate    │
│  Python/Java │──▶│  (parser)    │──▶│  (typed IR)  │──▶│  (emitter)   │──▶│  (Workbench  │
│  /C#/TS      │   │  ast/tree-   │   │  type map +  │   │  EnforceScript│   │  Validate-   │
│              │   │  sitter      │   │  diag        │   │  .c          │   │  Scripts)    │
└──────────────┘   └──────────────┘   └──────────────┘   └──────────────┘   └──────┬───────┘
                                                                                   │ report
                                                                        ┌──────────▼──────────┐
                                                                        │ 诊断报告 + 源映射    │
                                                                        │ (error/warning/info) │
                                                                        └─────────────────────┘
```

**阶段职责（每个阶段只做一件事，可独立单测）：**

1. **Frontend**（`frontends/`）：把源语言解析成统一的 **IR**。
   - Python：标准库 `ast`；未来 Java/C#/TS：tree-sitter 语法（§10）。
   - 前端只负责"结构抽取"，不做任何 EnforceScript 语义决策。
2. **IR + Sema**（`ir.py`、`sema/`）：语言无关的中间表示 + 类型解析。
   - 从类型注解映射类型（`list[int]` → `array<int>`）；无注解局部变量 → `auto`。
   - 收集类字段（`self.x = ...` 上提为字段声明）、检查受支持子集、产出诊断。
3. **Backend**（`backends/enforce.py`）：IR → EnforceScript 文本。
   - 缩进 → 花括号、`#` → `//`、`and/or/not` → `&&/||/!`、`None` → `null` 等。
   - 标识符保留字检查、字段上提、构造函数转换、f-string → `string.Format()`、三元 → if/else 展开。
4. **Validate**（`validate/workbench.py`）：把生成的 `.c` 部署进 addon 的 `scripts/` 树，
   调用 Workbench NET API `ValidateScripts`，把编译器的行号级错误映射回源 Python 行（source map）。
5. **CLI**（`cli.py`）：以上各阶段的编排入口 + 报告输出（terminal / JSON）。

**设计铁律**：
- 前端不产 EnforceScript 文本，后端不解析源语言——新增语言只写一个 frontend；
- 一切无法精确映射的构造必须产生诊断，禁止猜测生成；
- 所有输出文件头自动加 `// Generated by any2enforce — DO NOT EDIT`。

## 4. Python → EnforceScript 特性映射表（v0.1 子集）

### 4.1 词法/格式

| Python | EnforceScript | 说明 |
|---|---|---|
| 缩进块 | `{ }` | emitter 统一处理 |
| `#` 注释 | `//` 注释 | 逐行翻译；块注释 `"""..."""` → `/* ... */` |
| `'...'` / `"..."` | `"..."` | 统一双引号；转义按表 4.4 |
| 标识符 | 同名或 `snake_case`→`CamelCase` | 由 `naming` 配置控制；保留字冲突自动加 `_` 前缀并告警 |
| `True`/`False` | `true`/`false` | |
| `None` | `null` | |
| `self` | `this` | |

### 4.2 语句

| Python | EnforceScript | 备注 |
|---|---|---|
| `x = v` | `auto x = v;` 或 `T x = v;` | 有注解用 `T`，否则 `auto`（实测合法） |
| `x: T = v` | `T x = v;` | |
| `x += v` 等 | `x += v;` | `//`→`x = Math.Floor(...)`；`**`→`x = Math.Pow(...)` |
| `if / elif / else` | `if / else if / else` | |
| `while c:` | `while (c) { }` | |
| `for i in range(n)` | `for (int i = 0; i < n; i++)` | 实测同形（396 文件）；`range(a,b[,step])` 展开，负步进 `i -= n` |
| `for x in lst` | `foreach (T x : lst) { }` | 实测 `foreach (Class attr : ...)`；类元素自动加 `ref` |
| `break` / `continue` / `pass` | `break;` / `continue;` / 空 | |
| `return v` / `return` | `return v;` / `return;` | 三元值自动展开为 if/else return |
| `print(...)` | `Print(x)`；多参数 `PrintFormat("%1 %2", a, b)` | 实测 `Print(void var)` 任意类型；`PrintFormat` 支持 9 个参数 |
| `import X` | （无 import） | 记录为"模块依赖"注释；builtin 模块直接丢弃并告警 |
| `try/except` | ✗ | v0.1 error：EnforceScript 无异常机制（见 §7） |
| `with`、`global`、`nonlocal`、`del` | ✗ | error 诊断 |
| 函数/类 `def`/`class` | 见 §4.5 / §4.6 | |

### 4.3 表达式

| Python | EnforceScript | 备注 |
|---|---|---|
| `a + b`（数值） | `a + b` | |
| `a + b`（字符串） | `a + b` | 实测合法（`"\t" + msg`） |
| `a - b` `a * b` | 同 | |
| `a / b`（float） | `a / b` | int/int 结果类型 ⚠（见 VERIFY #6） |
| `a // b` | `Math.Floor(a / b)` | |
| `a % b` | int→`a % b`；float→`Math.Mod(a, b)` | 实测 `x % 360` 与 `Math.Mod` 均存在 |
| `a ** b` | `Math.Pow(a, b)` | 实测 `Math.Pow(float,float)` |
| `-x` / `not x` | `-x` / `!x` | |
| `a and b` / `a or b` | `a && b` / `a || b` | 非 bool 操作数告警（语义差异见 §6） |
| `== != < <= > >=` | 同 | 字符串 `==` 实测合法 |
| `x is None` | `x == null` | 实测 `if (x == null)` |
| `c if t else f` | **if/else 展开** | ❌ EnforceScript 无三元运算符（实测）；赋值/return 场景自动展开，表达式内嵌报错 |
| `x[i]` | `x[i]` | array/map/string 均实测支持 `[]` 读写 |
| `len(x)` | `x.Count()`（array/set/map）或 `x.Length()`（string） | 实测 `.Count()`（832 文件）、`.Length()`（string.c） |
| `x in lst` | `c.Contains(x)` | 实测 array/map/string 均支持 `.Contains()`（V06/P09） |
| `f"a={x} b={y}"` | `string.Format("a=%1 b=%2", x, y)` | 实测 `%1..%9` 占位符 |
| `str(x)` | `x.ToString()`（int/float）/`string.ToString(x)` | 实测两者均存在 |
| `int(x)` / `float(x)` | `(int)(x)` / `(float)(x)` | 实测 C 风格强转合法 |
| `min/max` | `Math.MinInt/MaxInt`（int）或 `Math.Min/Max` | 实测双套签名 |
| `abs(x)` | `Math.AbsInt/AbsFloat` | ❌ 无 `Math.Abs`（实测） |
| `[...]` 字面量 | `array<T> x = { ... };` | 实测初始化式语法；仅赋值场景，表达式内报错 |
| `{...}` dict 字面量 | `map<K,V> x = new map<K,V>();` + `x[k] = v;` | 实测 `new map<...>()` + `[]` 写 |
| `[...]` / `{...}` / `{k:v}` 推导式 | **赋值/return 展开**；嵌套表达式自动提升 `_pyLiftN` | foreach/for + Insert / `m[k]=v` |
| `lambda` / 闭包 / 生成器 | ✗ | v0.1 error；后续用回调/`ScriptCaller`（§7） |

### 4.4 字符串转义

Python 转义 `\n \t \" \\ \0` 与 EnforceScript 基本一致，直接透传；
⚠ 需检查：`\x..`/`\u....` 十六进制与 Unicode 转义、原始字符串 `r"..."`（可安全映射为普通字面量）。

### 4.5 模块级函数

```python
def add(a: int, b: int) -> int:      # →  int Add(int a, int b) { ... }
    return a + b
```

- 无返回注解 → `void`；无参数注解 → error + 可配置兜底类型（`untyped_param_fallback`，默认 `float`），
  输出中加 `// TODO[untyped-param]` 标记；
- 默认参数 `def f(a: int = 3)`：**EnforceScript 参数默认值合法（实测
  `void Print(string msg, LogLevel level = LogLevel.NORMAL)`）→ 直接映射 `int a = 3`**。

### 4.6 类与对象模型（核心难点）

```python
class Player(Base):
    def __init__(self, name: str, hp: int = 100):
        self.name = name            # → 字段上提 + 构造函数赋值
        self.hp = hp
    def damage(self, dmg: int) -> None:
        self.hp -= dmg              # → m_hp -= dmg;（裸字段访问，实测惯例）
    @staticmethod
    def max_hp() -> int:            # → static int MaxHp()
        return 999
```

| Python | EnforceScript |
|---|---|
| `class A(B):` | `class A : B`（单继承；多继承 → error，见 §7） |
| `__init__` | 构造函数 `void A(...)`（实测 `void SCR_AIDebugMessage(...)`） |
| `self.x = v` | 字段上提为类级声明 `T m_x;` + 构造/方法中 `m_x = v;`（**裸访问**，`m_` 前缀消歧） |
| 方法 `def m(self, a)` | `T M(T a)`；可见性由 `visibility` 配置（默认 `protected`） |
| `@staticmethod` | `static` 成员函数 |
| `@property` | v0.1 error；v0.2 生成 getter `T GetX()` / setter `void SetX(T)`（引擎无 property，⚠） |
| 类属性（`cls_var = 1`） | `static` 字段（v0.1 注释占位） |
| `ClassName.method(...)` / `instance.method(...)` | 同构（`.` 调用直接映射） |
| `super().__init__(...)` | v0.1 error；基类默认构造疑似隐式调用（⚠，`super(` 语料 0 命中） |
| 用户类类型（注解/参数/字段） | 自动加 `ref`（实测 `ref SCR_TimerEntryBase`、`array<ref SampleObject>`） |

**字段上提规则**：遍历类内所有方法体中 `self.<name> = <value>` 赋值，按
`name → (类型, 默认值)` 汇总；类型来自注解或首次赋值推断（默认 `auto` 不支持字段 → 需要显式类型，
推断失败给 error）。赋值保留在方法体内，同时声明字段。

### 4.7 类型映射

| Python 注解 | EnforceScript | 说明 |
|---|---|---|
| `int` `float` `bool` `str` | `int` `float` `bool` `string` | |
| `None`（返回） | `void` | |
| `list[T]` | `array<T>` | |
| `dict[K,V]` | `map<K,V>` | |
| `set[T]` | `set<T>` | |
| `tuple` | ✗ v0.1（error） | 后续映射为生成的容器类 |
| 用户类 | 同名类 | |
| `Optional[T]` / `T \| None` | `T`（空值用 `null`） | 需保证调用处空检查语义（生成时告警） |
| 无注解局部变量 | `auto` | EnforceScript 原生支持，安全兜底 |
| 无注解参数 | error + 配置兜底 | 见 §4.5 |
| `Any` / `object` | error | 动态类型无法表达 |

## 5. 核心设计决策

1. **IR 语言无关**：前端输出 IR，后端消费 IR。类型用 IR 类型对象（`ScalarType`/`ArrayType`/
   `MapType`/`ClassType`），杜绝在 emitter 里做字符串匹配。
2. **`auto` 作为局部变量兜底**：避免实现完整的类型推断（v0.1 不做数据流分析），
   同时保证输出是合法 EnforceScript。
3. **字段上提（hoisting）**：把 Python 动态实例属性收敛为 EnforceScript 类级字段声明——
   这是 OOP 映射里唯一需要跨方法分析的步骤，单独成 pass，可单测。
4. **诊断分级**：`error`（生成代码会被标记为不可用 / 跳过该构造）/ `warning`（语义近似，
   输出 `// TODO[...]` 注释）/ `info`（如 builtin import 被丢弃）。所有诊断带源位置
   （文件:行:列）与输出位置（source map）。
5. **验证闭环默认开启**：`--validate` 把生成文件写入目标 addon 的 `scripts/` 树后调用
   Workbench `ValidateScripts`；未运行 Workbench 时降级为"生成成功 + 提示手动验证"。
6. **命名策略可配置**：`keep`（保留 Python 命名，`snake_case` 在 EnforceScript 中合法）
   与 `camel`（方法/类转 CamelCase）两种模式；字段前缀 `field_prefix`（默认 `m_`，可空）。

## 6. 已知语义差异（转换时必须显式处理）

| 差异 | Python | EnforceScript | 处理 |
|---|---|---|---|
| 整数除法 | `7 // 2 == 3` | `/` 疑似 float 除法（⚠） | `Math.Floor(a / b)` + 告警 |
| 三元运算符 | `c if a else b` | **不存在（实测 ❌）** | 赋值/return 场景自动展开为 if/else；表达式内嵌 → error |
| 逻辑短路返回值 | `[] or [1]` 返回 `[1]` | `&&/||` 返回 bool | 操作数非 bool → 告警 |
| 动态类型 | 任意绑定 | 静态类型 | 注解缺失 → `auto`/error |
| 字符串不可变性 | 同 | 同 | 无 |
| 异常 | try/except | 无 | error + 建议改写为返回值/错误码模式 |
| 鸭子类型 | 运行时 | 编译期 | error + 建议显式接口类 |
| 多继承/MRO | 支持 | 单继承 | error + 建议 mixin→组合 |
| 装饰器 | 通用 | 仅少数属性（`[Attribute]` 等） | 白名单外 → error |
| 魔法方法 | `__eq__`/`__add__` | 运算符重载（⚠ 未见样本） | 白名单内 → 特殊映射，否则 error |

## 7. 不支持特性清单与降级策略（v0.1）

| 特性 | 诊断 | 建议 |
|---|---|---|
| `try/except/finally` | error | 返回值/错误码模式 |
| `with` 上下文管理 | error | 手动 acquire/release |
| 生成器 `yield` / `yield from` | error | 改为显式状态机或回调 |
| `lambda` / 闭包捕获 | error | `ScriptCaller` / 具名函数（v0.2） |
| `*args` / `**kwargs` | error | 显式参数（或 `array` 参数） |
| 装饰器（非白名单） | error | 手动展开 |
| 多继承 | error | 组合优先 |
| 动态属性/`setattr`/`__getattr__` | error | 显式字段 |
| `global`/`nonlocal` | error | 模块级状态 → `static` 字段 |
| 列表/字典/集合推导式 | ✔ 赋值/return 自动展开；嵌套表达式 → 临时变量提升 | 嵌套 for + if 过滤；`range` → 计数 for |
| 内置函数超出映射表 | warning | `// TODO[builtin:<name>]` |
| 模块级可执行代码（非函数/类） | warning | 包进 `Init` 函数（v0.2） |

> 原则：**推导式是唯一被"自动展开"的特性**（赋值/return；嵌套处先提升为临时变量），其余一律报错，保证"转换成功 = 语义可信"。

## 8. 输出布局与 CLI

```
any2enforce <input.py> --out <addon>/scripts/Game/<ns>/ \
    --target python --naming keep --validate
```

- `--out`：addon 的 `scripts/` 根；生成的 `.c` 写入 `scripts/Game/<模块名>/<原文件名>.c`
  （EnforceScript 惯例路径），头部自动带生成声明与源文件引用。
- 配置：`any2enforce.toml`（CLI 参数优先）：
  ```toml
  [naming]        policy = "keep"      # keep | camel
                  field_prefix = "m_"
  [types]         untyped_param_fallback = "float"
  [validate]      workbench_url = "http://127.0.0.1:12345"   # NET API 端口
                  addon_path = "../MyAddon"
                  deploy = true
  [targets]       active = ["python"]
  [builtins]      print = "Print"
  ```
- 报告：默认 terminal 摘要；`--report json` 输出机器可读诊断（含 source map），供 CI 使用。

## 9. 校验闭环（ValidateScripts）

生成代码的正确性以 **Workbench 编译结果为准**：

1. `validate/deploy`：把 `.c` 写入 addon `scripts/` 树（可 `--deploy` 开关）；
2. 调用 Workbench NET API `ValidateScripts`（与 `wb_bridge.py` 同一协议：
   `http://127.0.0.1:<port>/api/ValidateScripts`）；
3. 解析编译器返回的 `CompilerError[]`：按源映射把 `script.c (L:C)` 错误换算回 Python 源位置；
4. 结果合并进诊断报告；`--fail-on-error` 供 CI 使用；
5. 无 Workbench 时：`--validate` 提示不可用，不阻塞生成。

**这同时是映射表（§4 中所有 ⚠ 项）的自动验证手段**：`docs/VERIFY.md` 维护一张"验证用例"
清单，每个 ⚠ 项配最小用例，由 `tests/verify_workbench.py` 批量驱动。

## 13. 风险与已知限制

1. **float32 精度**：EnforceScript `float` = 单精度（游戏内训练对拍定案：epoch-0 loss
   0.504 ≈ float32 仿真 0.512，Python float64 为 0.653）→ 生成代码与 Python float64
   参考只保证**近似**一致；ML 训练本就以 float32 为业界标准；
2. **动态 Python 不可穷尽**：凡触及动态特性的代码必然需要人工改写——工具的价值在于
   把"能自动的部分"自动掉，把"不能的部分"精确暴露；
3. **字段上提的误判**：`self.x` 仅在部分分支赋值时，EnforceScript 字段声明语义
   （默认值 0/null）可能与 Python 的 `AttributeError` 不同 → 生成告警，建议显式初始化；
4. **性能**：`auto` 与数组/字典字面量展开可能产生非最优代码，后续可加优化 pass；
5. **无测试环境时**：金样只能保证"文本稳定"，不保证"编译通过"——本仓库已通过真机
   编译闭环（`verify/` 包 + 用户 Workbench）把该风险降到最低。
